مستندات API همکاری در فروش

این رابط برای همکارانی است که حسابشان تأیید شده، کیف پول دارند و می‌خواهند اکانت را بدون ورود به صندوق فروشگاه بخرند. پایهٔ آدرس:

https://example.com/wp-json/hooshmarket/v1

مبالغ عدد صحیح‌اند. اگر واحد پول فروشگاه تومان و بدون اعشار باشد، همان عدد تومان است. مشخصات ماشین‌خوان در openapi/openapi.yaml است.

احراز هویت

کلید را از پنل همکاری می‌سازید. فقط یک‌بار کامل نشان داده می‌شود و در پایگاه به‌صورت درهم‌ساز SHA-256 می‌ماند.

Authorization: Bearer hm_live_...

اگر برای کلید فهرست IP گذاشته باشید، فقط همان آدرس‌ها قبول می‌شوند. سقف پیش‌فرض ۶۰ درخواست در دقیقه است. پاسخ‌ها هدر X-RateLimit-Limit و X-RateLimit-Remaining دارند.

فهرست محصول

curl -sS "https://example.com/wp-json/hooshmarket/v1/products?per_page=20" \
  -H "Authorization: Bearer hm_live_YOUR_KEY" \
  -H "Accept: application/json"

price قیمت سطح شماست. retail_price قیمت ویترین است. stock موجودی اکانت قابل تحویل است، نه لزوماً موجودی انبار ووکامرس.

ثبت سفارش

هدر Idempotency-Key اجباری است. اگر شبکه قطع شد، همان کلید و همان بدنه را دوباره بفرستید. سفارش و کسر موجودی تکرار نمی‌شود. بدنهٔ متفاوت با همان کلید، خطای idempotency_conflict می‌دهد.

کمبود موجودی کیف پول کلید را مصرف نمی‌کند تا بعد از شارژ همان کلید را دوباره بفرستید. اگر سفارش ساخته شود و تحویل شکست بخورد، مبلغ برمی‌گردد، وضعیت failed می‌ماند و تکرار همان کلید همان نتیجه را برمی‌گرداند.

curl -sS -X POST "https://example.com/wp-json/hooshmarket/v1/orders" \
  -H "Authorization: Bearer hm_live_YOUR_KEY" \
  -H "Content-Type: application/json" \
  -H "Idempotency-Key: 6f1c0c3e-1b2a-4d55-9c3a-0b9e8a7d6c5b" \
  -d '{"product_id":120,"quantity":1,"reference":"inv-1001"}'

پاسخ ۲۰۱ فیلد credentials را با نام کاربری و رمز تحویل‌شده دارد. بعداً با GET /orders/120 همان اطلاعات را می‌گیرید. فهرست GET /orders رمزها را برنمی‌گرداند.

کیف پول

curl -sS "https://example.com/wp-json/hooshmarket/v1/wallet" \
  -H "Authorization: Bearer hm_live_YOUR_KEY"

curl -sS "https://example.com/wp-json/hooshmarket/v1/wallet/transactions?page=1" \
  -H "Authorization: Bearer hm_live_YOUR_KEY"

شارژ آنلاین با خرید محصولی انجام می‌شود که در ویرایش محصول، گزینهٔ «شارژ کیف پول» برایش روشن است. مبلغ پرداخت‌شده بعد از تکمیل سفارش به کیف پول همکار اضافه می‌شود. مدیر هم می‌تواند موجودی را دستی زیاد یا کم کند؛ هر دو در دفتر کل می‌مانند.

وب‌هوک

رویدادها: order.delivered و order.failed. بدنه JSON است و امضای HMAC-SHA256 آن در هدر X-HooshMarket-Signature با پیشوند sha256= می‌آید. رمز امضا در پنل همکاری و در GET /me است.

PUT /me/webhook
{"url":"https://partner.example/hooks/hooshmarket"}

اگر پاسخ شما ۲xx نباشد، ارسال تا ۵ بار با فاصلهٔ ۱، ۵، ۱۵، ۶۰ و ۳۶۰ دقیقه تکرار می‌شود. شناسهٔ id رویداد را برای جلوگیری از پردازش دوباره نگه دارید.

$expected = 'sha256=' . hash_hmac('sha256', $rawBody, $secret);
$ok = hash_equals($expected, $_SERVER['HTTP_X_HOOSHMARKET_SIGNATURE'] ?? '');

شکل خطا

همهٔ خطاها این شکل را دارند. request_id همان هدر X-Request-Id است و در لاگ مدیر دیده می‌شود. بدنهٔ درخواست، کلید و رمز اکانت در لاگ ذخیره نمی‌شود.

{"error":{"code":"insufficient_funds","message":"موجودی کیف پول کافی نیست.","request_id":"ab12cd34ef56ab78"}}
